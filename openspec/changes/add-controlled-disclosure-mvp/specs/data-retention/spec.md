# Delta for data-retention

## ADDED Requirements

### Requirement: Сроки хранения
Система SHALL применять сроки хранения из design.md §8. Значения MUST задаваться в конфигурации (env), а не в коде.

#### Scenario: Конфигурация сроков
- **WHEN** приложение стартует
- **THEN** сроки читаются из `RETENTION_*` переменных, при отсутствии используются значения по умолчанию из design.md

### Requirement: Автоматическая очистка
Фоновая задача SHALL раз в час: помечать истёкшие grants (`grant.expired`) и удалять их сессии; удалять использованные/истёкшие
magic links старше 24 ч; обезличивать запросы с истёкшим `retain_until` (обнулить `email_enc`, `email_hash`, `display_name`,
`purpose`, статус `purged`). Каждый запуск пишет одно событие `retention.purged` с количеством затронутых записей (без содержимого).

#### Scenario: Истечение grant
- **GIVEN** grant с `expires_at` в прошлом
- **WHEN** выполняется retention-джоба
- **THEN** grant помечен истёкшим, его сессии удалены

#### Scenario: Обезличивание запроса (демо)
- **WHEN** выполнен `make retention-run NOW_OFFSET=31d`
- **THEN** отклонённые запросы старше 30 дней имеют пустые персональные поля и статус `purged`

### Requirement: Ручное удаление
Admin SHALL иметь возможность досрочно обезличить запрос (например, по просьбе requester) и удалить материал карточки
(запись + файл на диске; при наличии активных grants с этим материалом — материал исключается из них).
Удаление подтверждается повторным вводом и фиксируется в аудите.

#### Scenario: Удаление материала
- **WHEN** admin удаляет материал
- **THEN** файл отсутствует на томе, запись удалена, grants больше не содержат его ID, событие `material.deleted`
